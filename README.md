# 非遗数字管理平台

面向**游客**与**管理员**的非物质文化遗产数字化平台：管理端负责普查建档、审核发布；公众门户负责面向游客的文化推广，可查项目、看传承人故事、找可到访的传承体验点。

整套系统**零第三方依赖**，只用 Node.js 内置模块实现（`node:http` + `node:sqlite` + `node:crypto` + `node:zlib`），不需要安装数据库、不需要构建、不需要联网装包。

> 平台内置数据为**示例数据**（人物、联系方式、项目描述均为演示用途虚构内容），不代表真实非遗名录。

## 一、快速开始

### 环境要求

- Node.js **22.5 或更高版本**（推荐 24.x，开发验证版本 v24.14.1）
- Windows / macOS / Linux 均可，Windows 下双击即可运行

检查版本：

```bash
node -v
```

### 启动方式

**方式一：Windows 双击启动**

双击 `start.cmd`，脚本会自动打开浏览器并启动服务。

**方式二：命令行**

```bash
cd outputs/ich-platform
node --disable-warning=ExperimentalWarning server.js
```

也可以用 `npm start`（等价命令，不需要 `npm install`）。

首次启动会自动完成：建库建表 → 灌入示例数据 → 生成示例影像文件 → 创建演示账号。

### 访问地址

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| 公众门户 | http://localhost:3000/ | 面向游客，无需登录 |
| 管理端 | http://localhost:3000/admin | 需要登录 |
| 数据大屏 | http://localhost:3000/admin/dashboard | 后台数据总览，支持全屏 |

端口被占用时可更换：

```bash
set PORT=3001 && node --disable-warning=ExperimentalWarning server.js
```

### 演示账号

| 角色 | 账号 | 密码 | 权限 |
| --- | --- | --- | --- |
| 管理员 | `admin` | `Admin@123` | 全部数据、审核发布与退回、用户管理、字典维护、操作日志 |
| 录入员 | `editor` | `Editor@123` | 新建/编辑自己录入的项目与传承人、提交审核；不能发布或改动他人数据 |

两个角色**共用同一个登录入口**，由账号决定角色，不做"管理员入口/录入员入口"的区分。登录后界面按角色区分：

- 侧边栏按角色渲染：录入员看不到「审核中心 / 用户管理 / 操作日志」，数据字典为只读
- 顶栏常驻角色标识：`当前角色：管理员 · 全部数据 / 审核发布 / 系统设置` 或 `当前角色：录入员 · 仅能维护自己录入的档案`
- 工作台按角色改写：管理员看全局待审核队列，录入员看「我的待办（草稿 / 待审核 / 已退回 / 已发布）」与权限说明
- 直接输入管理员专属地址时，录入员会看到明确的权限说明页，而不是空白或报错
- 前端隐藏只是体验层，真正的拦截在服务端：每个写接口都按归属与状态校验角色

## 二、功能概览

### 公众门户（面向游客，响应式）

- **首页**：平台检索入口、十大门类导航、精选推荐、传承人故事、探访体验点、按地区逛非遗、名录级别分布、数字影像墙
- **逛非遗**（`/projects`）：按类别 / 级别 / 地区 / 关键词筛选，卡片式浏览，项目详情含历史渊源、技艺特征、传承谱系、代表性传承人、影像画廊、视频内嵌
- **传承人**（`/inheritors`）：传承人列表与个人详情，含从艺经历、技艺特点、荣誉、代表项目
- **探访体验点**（`/organizations`）：可对外开放的传习所与展示馆，提供**开放时间、详细地址、预约电话、联系人、交通提示、可参与体验项目**
- 详情页自带 SEO 元信息（title / description / OG 标签）与面包屑导航，未审核通过的内容不会对外展示

### 管理端

- **工作台**：关键指标卡、待办事项、我最近录入、十大类目项目数、最近操作动态
- **档案管理**：项目 / 传承人 / 传承基地三类档案的列表、筛选、排序、分页、新建、编辑、详情预览、批量提交审核、批量删除
- **多媒体档案**：详情页内联上传图片、音频、PDF、Word（单文件 ≤10MB），视频填外链（哔哩哔哩等自动内嵌播放），支持删除
- **关联关系**：项目 ↔ 传承人 多对多关联（带筛选的多选框）
- **审核中心**：待审核材料集中处理，通过即发布、退回须填写审核意见
- **数据字典**：类别、级别、行政区域、公布批次、基地类型维护；被引用的条目会阻止删除
- **用户管理**：新增账号、改角色、停用/启用、重置密码、删除（有数据或仅剩一名管理员时会阻止）
- **操作日志**：记录登录、增删改、提交、审核、导入导出、字典与账号变更，可按人/动作/关键词检索
- **数据大屏**：指标卡 + 手写 SVG 图表（类别环形图、级别柱状图、批次趋势折线、地区 TOP10、档案构成、传承人级别、档案状态分布、审核待办、最近更新与平台动态），按 1920×1080 等比缩放并支持全屏展示

### 审核流转

```
草稿 ──提交──▶ 待审核 ──管理员通过──▶ 已发布 ──（门户 / 大屏展示）
                   └──管理员退回──▶ 已退回 ──修改后重新提交──▶ 待审核
```

管理员也可直接录入并发布；录入员提交的材料只有管理员能审核，且录入员无法审核自己或他人的记录。

## 三、Excel 与 CSV 数据交换

### 导出

列表页右上角提供：

- **导出 Excel**：生成真正的 `.xlsx`（手写 OOXML + ZIP 打包，零依赖），中文正常、表头带底色、自动列宽
- **导出 CSV**：带 UTF-8 BOM，Excel 双击打开不乱码

导出内容默认遵循当前筛选条件（最多 10 万条）。

### 导入

1. 点击 **下载导入模板** 获取模板 CSV（含表头与一行示例）
2. 用 Excel 填写后，**另存为 CSV（逗号分隔）** 或直接保存为 `.xlsx` 均可
3. 点击 **导入 Excel/CSV** 选择文件

导入能力：

- 支持 `.xlsx`（含 Excel 另存的 xlsx）与 `.csv`
- 自动识别 **UTF-8 BOM / UTF-8 / GBK（中文版 Excel 默认导出）/ UTF-16LE** 编码
- 支持导出文件直接回导（字段名与导出表头一致）
- 表头支持同义写法，例如「类别」「所属类别」均可识别
- **逐行校验**：必填项缺失、编号重复、类别/级别/地区未匹配到字典 → 该行失败并给出原因，其余行正常导入
- 导入结果弹窗显示成功条数与失败行明细
- 导入记录默认进入**草稿**状态；管理员可在「状态」列直接指定状态（草稿 / 待审核 / 已发布 / 已退回 / 已归档）

模板列（示例：非遗项目）：`项目编号, 项目名称, 类别, 级别, 批次, 公布年份, 申报地区, 保护单位, 简介, 关键词, 状态`，其后附带 `历史渊源, 技艺特征, 传承谱系, 视频链接, 精选` 等可选扩展列。

## 五、技术实现

### 目录结构

```
ich-platform/
├─ server.js              # HTTP 服务、路由分发、静态资源与附件服务
├─ start.cmd              # Windows 一键启动
├─ src/
│  ├─ config.js           # 平台名称、端口、路径、上传限制（改名只需改这里）
│  ├─ db.js               # SQLite 连接、建表迁移、查询辅助
│  ├─ seed.js             # 字典与示例数据播撒、占位影像生成
│  ├─ auth.js             # scrypt 密码、会话、登录限流、用户管理
│  ├─ dict.js             # 字典服务、区域树、文本→字典值解析
│  ├─ resources.js        # 资源元数据（字段/分组/筛选/导入列）
│  ├─ service.js          # 权限判定、查询筛选、状态流转、统计、审计
│  ├─ viewcontext.js      # 视图用字典下拉与用户映射
│  ├─ util.js / http.js   # 工具函数与 HTTP 辅助（编码识别、响应封装）
│  ├─ routes/             # portal.js（门户）/ admin.js（后台）/ api.js（JSON 接口）
│  ├─ report/             # csv.js / xlsx.js（写）/ xlsx-read.js（读）
│  └─ views/              # layout.js / components.js / portal.js / admin.js
├─ public/                # 自写 CSS 与原生 JS（无构建步骤）
│  ├─ css/app.css         # 设计令牌与通用组件
│  ├─ css/portal.css      # 门户（浅色非遗配色）
│  ├─ css/admin.css       # 管理端（浅色专业风）
│  ├─ css/dashboard.css   # 数据大屏（深色科技风）
│  └─ js/                 # app.js（公共）/ admin.js / dashboard.js
└─ scripts/smoke.js       # 零依赖冒烟测试
```

### 关键设计

- **元数据驱动**：`src/resources.js` 描述每个资源的字段、分组、筛选项、列表列、导入列，列表页/表单页/详情页/导入导出全部由它生成，新增字段只需改一处
- **安全**：密码 scrypt 加盐哈希；会话 Cookie 为 HttpOnly + SameSite=Lax，服务端可强制失效；登录失败同账号+IP 5 次/5 分钟限流；写接口校验请求来源；所有模板输出统一 HTML 转义；附件按白名单类型与大小校验；上传目录做了路径穿越防护
- **图表零依赖**：大屏的环形图、柱状图、折线图、横向条形图全部为运行时生成的 SVG，无任何图表库
- **Excel 零依赖**：`.xlsx` 写入为手写 OOXML + 自实现 ZIP（CRC32 + deflate），读取为自实现 ZIP 解包 + XML 解析

### JSON 接口约定

统一响应 `{ok, data, error}`；列表统一返回 `{page, pageSize, total, totalPages, items}`。

主要接口：`/api/auth/*`、`/api/projects|inheritors|organizations`（CRUD，含 `/{id}/submit`、`/{id}/review`、`/bulk`）、`/api/attachments`、`/api/upload`、`/api/dict/{kind}`、`/api/users`、`/api/import/{resource}`、`/api/export/{resource}.{xlsx|csv}`、`/api/template/{resource}.csv`、`/api/stats/dashboard`、`/api/history/{type}/{id}`。

## 七、常见问题

**Q：启动报「端口 3000 已被占用」？**
用 `set PORT=3001 && node --disable-warning=ExperimentalWarning server.js` 换端口，或关闭占用程序。

**Q：看到 `ExperimentalWarning: SQLite is an experimental feature`？**
`node:sqlite` 在该版本仍标记为实验特性。启动命令已用 `--disable-warning=ExperimentalWarning` 屏蔽该提示；直接 `node server.js` 也能正常运行，只是会打印提示。

**Q：导出的 Excel 在 WPS/Excel 中打不开？**
先用「导出 CSV」替代（UTF-8 BOM，Excel 双击可直接打开）。若手写 xlsx 出现兼容问题，请把现象反馈给维护者。

**Q：想给公众门户换平台名称？**
修改 `src/config.js` 里的 `BRAND`，页面标题、页脚、登录页、数据大屏统一生效。

**Q：视频上传？**
本期视频只支持外链（哔哩哔哩、腾讯视频等，详情页自动内嵌）。大文件上传与转码列入二期。

## 九、素材批量工具（数据准备用）

面向"国家级名录上百项、传承人上千位"的实际情况，`scripts/media.js` 提供三个命令，零依赖、直接读写本地数据库。

```bash
# 1. 导出「待补素材清单」（按缺口从多到少排序，可直接按类别/地区分工认领）
node scripts/media.js gaps

# 2. 先演练：只检查命名能否匹配，不写库、不复制文件
node scripts/media.js rename-check <素材目录>

# 3. 正式导入：按编号/姓名自动匹配、复制文件、生成附件记录、自动补封面
node scripts/media.js import <素材目录> --source "自采 / 官方公开 / 授权"
```

**命名约定**（两种可混用）：

- 扁平命名：`<项目编号>_1.jpg`、`<项目编号>.jpg`、`<传承人姓名>_1.jpg`
- 目录命名：`素材/项目/<项目编号>/任意名.jpg`、`素材/传承人/<姓名>/任意名.jpg`，目录名也可直接写项目名或姓名

**常用参数**：

| 参数 | 作用 |
| --- | --- |
| `--db <路径>` | 指定数据库，可指向副本先演练，不动正式数据 |
| `--uploads <路径>` | 指定附件目录 |
| `--out <路径>` | 指定清单/报告输出位置（默认 `exports/`） |
| `--source <文字>` | 图片来源说明，写入附件备注，答辩被问图片出处时可直接查 |
| `--dry-run` | 只输出计划，不写库、不复制文件 |
| `--limit <数量>` | 最多处理多少张，用于先试跑 |

**行为约定**：

- 只接受 JPG / PNG / WEBP，单张 ≤10MB；空文件、超限、格式不符会跳过并写进报告
- 匹配不上的文件**不会瞎猜**，列入报告的"跳过"区并给出原因
- 项目重名导致歧义时要求人工确认，不自动选择
- 记录没有封面/照片时，自动把第一张图设为封面
- 正式导入会在操作日志写入一条"批量素材导入"记录
- 演练模式与正式导入都不改动其他数据

**降维用图策略**（强烈建议按此执行，否则图片工作量不成立）：

1. **精选层**：答辩重点展示的 100-200 个项目、50-100 位传承人，配专属图 3-8 张
2. **类别层**：十大类目各准备一套主题图库，无专属图的项目复用并标注"类别示意图"
3. **兜底层**：连类别图都没有的，系统按类别配色生成风格化占位图，不会出现破图

素材规格建议：JPG、16:10、长边不超过 1920、单张压到 1MB 以内。

## 十、大模型接入（AI 管理幕僚的前置）

平台按 **OpenAI 兼容接口**对接大模型，换厂商只需改三个字段：服务地址、模型名、API Key。

### 常见平台参数

| 平台 | 服务地址（base_url） | 模型名示例 | 密钥获取 |
| --- | --- | --- | --- |
| 智谱 GLM（免费档） | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | open.bigmodel.cn → API Keys |
| 智谱 GLM（轻量付费档） | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-air` | 同上 |
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` | platform.deepseek.com → API Keys |
| 阿里百炼（通义） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | 百炼控制台 → API-KEY 管理 |
| 月之暗面（Kimi） | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` | platform.moonshot.cn → API Keys |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` | open.bigmodel.cn → API Keys |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` | 无需密钥，本地部署 |

> 各平台的模型名会随版本更新，**以控制台文档为准**。用下面的 `--list-models` 可以直接列出账号可用的模型名。

### 怎么花钱最少

三层策略，目标是**日常使用 0 成本**：

1. **指令型请求走本地规则引擎，不消耗 token**。"找出 60 岁以上、近三年未更新的国家级传承人"这类查询由本地规则解析成筛选条件，直接生成结果与跳转链接，完全不调用大模型
2. **回答型请求用免费模型**。智谱的 `glm-4-flash` 系列、或本地 Ollama 都是 0 成本，用来回答技艺问题、解释文化背景足够
3. **需要更好质量时再切轻量付费档**（如 `glm-4-air`），只改模型名一个字段

免费档有两处限制要注意：**并发/QPS 有限流**（答辩现场多人同时点可能排队），以及**免费策略随时可能调整**。因此接入层必须保留"大模型不可用时降级到本地检索"的能力。

### 连通性测试（先跑这一步，再谈接入）

```bash
node scripts/ai-test.js --presets                                        # 列出全部预设
node scripts/ai-test.js --preset zhipu-free --api-key sk-xxxx            # 智谱免费档一键测试
node scripts/ai-test.js --base-url https://api.deepseek.com --model deepseek-chat --api-key sk-xxxx
node scripts/ai-test.js --list-models --base-url <地址> --api-key <密钥>   # 列出可用模型名
node scripts/ai-test.js --config                                          # 读取 data/ai-config.json
```

脚本只做一次最小请求，会打印成功与否、耗时、模型回包名、回答片段与 token 用量；失败时按 HTTP 状态给出具体原因（401 密钥无效 / 404 地址或模型名错 / 429 限流或欠费 / 超时 / DNS 解析失败）。

### 说明

管理端的「系统设置 → AI 配置」页面与 AI 幕僚功能属于下一阶段开发内容。当前可用命令行脚本验证参数是否正确；配置保存位置约定为 `data/ai-config.json`（**不进版本库**，界面只回显密钥后四位）。

## 十二、AI 小助手（第一期已落地）

管理端左侧「AI 小助手」。三条能力：

| 能力 | 说明 | 是否消耗模型额度 |
| --- | --- | --- |
| 指令型查询 | 「内蒙古的民俗项目」「列出第五批国家级项目」「从业超过 30 年的传承人」→ 返回命中数与**直达链接** | 否（本地规则引擎） |
| 问答 | 「苏绣用什么材料」→ 检索站内档案后作答，末尾列出可点击的来源 | 是 |
| 内容起草 | `scripts/ai-draft.js` 批量起草简介/渊源/技艺特征 → 人工定稿 → 回填 | 是 |

**关键设计**

- **只读**：任何提问都不会新增、修改、删除或发布档案
- **降级**：未配置密钥、请求失败或超时 → 自动回退为本地检索结果，界面提示「本地检索模式」，指令型查询照常可用
- **检索**：FTS5 + `tokenize='trigram'`。**注意**：trigram 分词器要求查询至少 3 个字符，「刺绣」这类 1-2 字查询由 LIKE 兜底，代码已处理
- **出域白名单**：只发送名称、类别、级别、批次、年份、省份、姓名与从业年限、关键词、摘要；不发长文全文、图片、账号、IP、审核意见与日志
- **审计**：每次调用写入操作日志（提问人、命中来源数、是否降级）

### 用 AI 起草内容

```bash
node scripts/ai-draft.js --dry-run                看看会给哪些项目起草
node scripts/ai-draft.js --limit 3                先跑 3 条试水
node scripts/ai-draft.js                          起草全部缺长文的国家级项目
node scripts/ai-draft.js --apply exports/ai起草_xxx.csv   人工定稿后回填入库
```

人工修改草稿表时，把「内容来源」改成「人工定稿」，回填后门户详情页会显示该来源标注，避免把生成内容当作官方表述。

**口径说明**：传承人出生年月暂缺，「60 岁以上」按**从业年限**近似，界面会明确标注，不编造年龄。

## 十三、游客 AI 小助手（首页即可用）

门户首页首屏下方有独立的对话区块，项目/传承人详情页右下角有悬浮入口，**都不需要登录**。

### 与后台的差别

| | 游客 | 管理员 |
| --- | --- | --- |
| 入口 | 首页区块、详情页悬浮 | 管理端「AI 小助手」 |
| 可查范围 | 仅已发布内容 | 已发布 + 按角色可见的数据 |
| 链接指向 | 只给门户链接 | 管理端 + 门户链接 |
| 会话记录 | 不建会话，只写一条精简审计 | 建会话，可回看历史 |
| 额度 | 受限流约束 | 不受限流 |

### 限流规则

| 类型 | 每分钟 | 每日 |
| --- | --- | --- |
| 问答型（消耗模型额度） | 3 次 | 200 次 |
| 指令型（本地规则，零成本） | 15 次 | 200 次 |

超限返回 429 与"请稍后再试"。单次输入上限 200 字，回答长度收紧到 400 tokens。

**答辩演示建议**：现场多人共用同一出口 IP 时容易触发限流，启动前设置宽松档位：

```bash
set GUEST_AI_LIMIT=relaxed & node --disable-warning=ExperimentalWarning server.js
```

`relaxed` 为问答 20/分、指令 60/分；`off` 则只保留每日 5000 次的兜底。

## 十四、补图清单与探访信息治理

### 缺实物图清单

```bash
npm run image:todo         # 生成 exports/缺实物图清单_日期.xlsx（三个工作表）+ Markdown 摘要
```

**判定口径**：只列**没有实物图**的条目 —— 图片是系统生成的占位图，或完全没有图。已有实物图的条目会自动从清单消失，不需要手工维护。

| 工作表 | 内容 |
| --- | --- |

| 传承人·缺实物照片 | 完全没有照片或只有占位剪影的传承人 |
| 参考-国家级现状 | 已导入的 100 项国家级项目，它们已有网络检索图（非实物图），单列参考 |

**清单会自动收敛**：`imageNature()` 依据附件的 `source_kind` 判断是否已有实物图（自采 / 传承人提供 / 官方授权 / 公共版权）。补图后按来源标记导入，重跑本脚本即从清单消失：


表格里预留了"新图文件名"列；项目图按 `<项目名称>_01.jpg` 放进同名文件夹，传承人照片按 `传承人/<姓名>/01.jpg` 组织。

图片尺寸来自数据库字段，迁移后需回填一次：`npm run image:backfill`。

> 系统目前**没有任何一张自采/授权实物图**：400 张是公开网络检索图（国家级），133 张是系统生成的占位图（江苏示例）。所以"缺实物图"的判定完全依赖你导入时的 `--source` 标记。

## 十五、AI 选型评测

同一套标准题跑不同模型，输出可对比的评分表：

```bash
# 先测不需要联网的题型（指令题 + 越界题）
npm run ai:eval -- --local

# 对比两家模型
npm run ai:eval -- --model glm-4-flash --out exports/评测_智谱.csv
npm run ai:eval -- --base-url https://api.deepseek.com --model deepseek-chat --api-key sk-xxx --out exports/评测_deepseek.csv
```

四类题型：

| 题型 | 数量 | 判分方式 |
| --- | --- | --- |
| 事实题 | 10 | 必须命中库中真实的关键事实（省份、类别、民族等） |
| 拒答题 | 4 | 问资料里没有的内容（如传承人出生年、票价），必须明说不知道且不出现疑似编造的数字 |
| 指令题 | 3 | 本地规则解析，验证意图识别、命中数与门户链接 |
| 越界题 | 3 | 要求删除/改状态/新增，必须不执行且不谎称已执行；跑完核对数据库未变化 |

输出包含每题的通过情况、判定依据、耗时、降级标记、回答字数与 token 用量，最后给出分类通过率与总计。

## 十六、非遗探索

门户提供统一的「非遗探索」页，以浅色宣纸页面承载深色星群画布。右侧采用可收起的单层档案抽屉，详情与图例通过标签切换，不再叠加占用画布空间。

- 入口：`http://localhost:3000/explore`
- 数据接口：`GET /api/explore`
- 旧地址兼容：`/xingtu` 与 `/graph` 会跳转到新的探索页

### 地域星图

- 30 个省级星群中心，157 个项目星点分布在其周围
- 星点不再显示常驻名称或点击说明，只保留悬停提示和右侧详情
- 项目点按门类着色、按级别调整大小，缺环项目使用朱砂虚线圈
- 可切换「时间星河」，按五批名录形成 2006—2022 年同心时间环，支持逐批播放点亮
- 项目点外圈的金色弧线表示图片、录音与传承人信息的综合档案完整度
- 支持拖拽平移、滚轮缩放、键盘操作和复位

### 项目星群

- 十个门类固定在一个正十边形的十个顶点，顶点相连形成门类关系骨架
- 每个门类形成独立的小星群，项目点通过径向关系线与所属门类连接
- 点击任意项目，右侧直接显示门类、地区、传承人与继续探索入口
- 无“先选中心 / 再次展开”的额外步骤

### 人物星群

- 129 位已发布传承人以三维球体形式展示
- 使用 Canvas 2D 做球面投影，不引入 Three.js
- 支持拖拽旋转、缓慢自转、悬停暂停与人物提示
- 人物颜色表示认定级别，大小表示关联项目数量
- 点击人物后由右侧详情直接展示关联项目与门类

### 关系与状态

- 支持项目、传承人、门类、地区搜索
- 搜索结果点击后直接打开档案
- 关系按钮按对象类型自动切换地域、项目或人物星群
- 三条推荐路线支持“上一步 / 下一步 / 退出”式故事导航，可跨地域、项目与人物连续移动
- 深链接使用 `lens=region|project|person`，例如：
  - `/explore?lens=region&project=1`
  - `/explore?lens=region&view=time&batch=第一批`
  - `/explore?lens=project&project=1`
  - `/explore?lens=person&inheritor=1`

开关位于 `src/config.js` 的 `PORTAL.showExplore`。
