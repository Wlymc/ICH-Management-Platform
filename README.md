# 非遗数字管理平台

面向游客与非遗管理人员的非物质文化遗产数字化一体化平台，覆盖**资源普查建档、审核流转发布、公众文化展示、AI数字讲解、星图关系探索**五大核心场景。管理端负责非遗项目、传承人、传承基地的全生命周期管理与审核发布；公众门户面向游客提供非遗名录检索、传承人故事、探访体验线索、沉浸式文化探索服务。

系统基于 Node.js 原生能力构建，**零第三方运行时依赖**，无需安装数据库、无需构建前端产物即可启动运行，轻量化易部署。内置国家级非遗示范数据，所有演示素材仅用于教学展示。

## 二、技术架构

### 2.1 整体分层架构
系统采用四层权责分离架构，低耦合易扩展：
1. **接入层**：HTTP 服务与路由分发，处理静态资源响应、附件上传、接口请求鉴权
2. **业务层**：权限校验、状态流转、数据筛选、统计审计、字典服务、AI 适配调度
3. **数据层**：SQLite 原生数据库、FTS5 全文检索、Excel/CSV 结构化数据交换
4. **展示层**：管理端服务端模板 + 公众端 React 单页应用

### 2.2 技术栈明细
#### 后端与管理端
- 运行时：Node.js 22.5+，仅使用**原生内置模块**（`node:http` / `node:sqlite` / `node:crypto` / `node:zlib`）
- 数据库：SQLite（WAL 高性能模式），内置 FTS5 全文检索引擎
- 管理端：服务端模板渲染 + 原生 CSS/JavaScript，无前端框架依赖
- 自研组件：手写 OOXML 实现 Excel 读写、运行时生成 SVG 图表，全程零第三方依赖库

#### 公众前端
- 核心框架：React 19 + TypeScript Strict + Vite 7
- 状态与数据：Zustand 全局状态 + TanStack Query 服务端状态
- 路由方案：React Router 6
- 工程化：ESLint + Prettier 代码规范、Vitest + Playwright 测试

### 2.3 核心设计特色
- **元数据驱动**：通过 `src/resources.js` 统一配置所有资源的字段、筛选规则、导入导出列，新增字段仅需修改一处，自动同步表单、列表、详情页与接口
- **全链路安全**：scrypt 加盐密码哈希、HttpOnly+SameSite 会话 Cookie、登录失败限流、接口服务端权限校验、上传路径穿越防护、输出统一 HTML 转义
- **零依赖工程**：图表渲染、Excel 解析生成、压缩解压均自主实现，运行时无需安装任何 npm 包
- **AI 降级容灾**：大模型不可用时自动降级为本地检索，保证核心查询功能可用

### 2.4 AI 能力架构
采用 OpenAI 兼容接口标准，支持多厂商模型无缝切换，内置三层成本优化策略：
1. 指令型查询：本地规则引擎解析语义，直接检索数据库，**零 token 消耗**
2. 常规问答：调用免费大模型，满足日常文化科普需求
3. 高质量生成：按需切换轻量付费模型，平衡效果与成本

已适配平台：智谱 GLM 全系列、DeepSeek、阿里通义、月之暗面 Kimi、本地 Ollama

## 三、安装运行指南

### 3.1 环境要求
- Node.js **22.5 及以上版本**（推荐 24.x LTS）
- 全平台兼容：Windows / macOS / Linux
- 后端运行无需执行 `npm install`，仅重新构建前端时需安装依赖

### 3.2 启动步骤
#### 方式一：Windows 一键启动
双击项目根目录下的 `start.cmd`，脚本将自动启动服务并打开浏览器访问门户。

#### 方式二：命令行启动
```bash
# 拉取项目代码
git clone [https://github.com/Wlymc/ICH-Management-Platform.git](https://github.com/Wlymc/ICH-Management-Platform.git)
cd ICH-Management-Platform

# 复制环境变量配置文件
cp .env.example .env

# 启动服务
npm start
```

> 端口被占用时，可通过 `PORT=3001 npm start` 指定端口启动。

### 3.3 访问入口
| 入口 | 地址 | 说明 |
| :--- | :--- | :--- |
| 公众门户 | [http://localhost:3000/](http://localhost:3000/) | 面向游客，无需登录 |
| 管理后台 | [http://localhost:3000/admin](http://localhost:3000/admin) | 需账号登录 |
| 数据大屏 | [http://localhost:3000/admin/dashboard](http://localhost:3000/admin/dashboard) | 数据总览看板，支持全屏展示 |

### 3.4 演示账号
| 角色 | 账号 | 密码 | 权限范围 |
| :--- | :--- | :--- | :--- |
| 管理员 | `admin` | `Admin@123` | 全部数据管理、审核发布、用户管理、系统配置 |
| 录入员 | `editor` | `Editor@123` | 新建/编辑本人录入的档案、提交审核，不可发布或修改他人数据 |

> 权限控制在服务端实现，前端仅做体验层适配，越权访问将被接口拦截。

### 3.5 核心环境变量
| 变量 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `PORT` | `3000` | HTTP 服务端口 |
| `HOST` | `0.0.0.0` | 服务监听地址 |
| `AI_ENABLED` | `true` | 是否启用 AI 功能 |
| `AI_BASE_URL` | `[https://open.bigmodel.cn/api/paas/v4](https://open.bigmodel.cn/api/paas/v4)` | 大模型接口地址 |
| `AI_MODEL` | `glm-4-flash` | 调用的模型名称 |
| `AI_API_KEY` | 空 | 模型密钥，仅服务端读取 |
| `GUEST_AI_LIMIT` | `normal` | 游客 AI 限流档位 |

## 四、核心功能

### 4.1 公众门户（游客端）
- **首页导览**：全站检索入口、十大门类导航、精选推荐、传承人故事、探访线索、数字影像墙
- **非遗名录**：按类别/级别/地区/关键词多维度筛选，卡片式浏览；详情页包含历史渊源、技艺特征、传承谱系、影像画廊
- **传承人档案**：传承人列表与个人详情，涵盖从艺经历、技艺特点、荣誉奖项、代表项目
- **探访体验**：展示传习所与展示馆信息，包含开放时间、详细地址、预约方式、交通提示
- **非遗探索**：星图可视化交互，支持地域星群、项目关系、人物网络三种视角，拖拽缩放、路径导航
- **数字讲解员**：浏览器原生语音播报，支持简短/详细/儿童版讲解词，无需调用大模型

### 4.2 管理后台
- **工作台**：核心指标看板、待办事项、最近录入动态、类目分布统计
- **档案管理**：项目、传承人、传承基地三类档案的增删改查、筛选排序、批量提交/删除
- **多媒体管理**：支持图片、音频、PDF、Word 附件上传，视频支持外链内嵌播放
- **关联配置**：项目与传承人多对多关联关系维护
- **审核中心**：待审核材料集中处理，通过即发布、退回需填写审核意见
- **数据字典**：类别、级别、行政区域、公布批次等基础数据维护
- **用户管理**：账号新增、角色变更、停用启用、密码重置
- **操作日志**：全量操作记录，支持按人、动作、关键词检索
- **数据大屏**：多维度 SVG 图表，涵盖类别分布、级别统计、批次趋势、地区排名等

### 4.3 审核流转机制
```
草稿 → 提交审核 → 待审核 → 管理员通过 → 已发布（门户/大屏展示）
                        ↘ 管理员退回 → 已退回 → 修改后重提
```
- 管理员可直接录入并发布内容
- 录入员仅可提交本人档案，无法审核任何记录
- 未通过审核的内容不会在公众门户展示

### 4.4 数据导入导出
- **导出**：支持 Excel（.xlsx）与 CSV 格式，导出内容跟随当前筛选条件，最多支持 10 万条
- **导入**：支持 xlsx/csv 文件，自动识别 UTF-8/GBK/UTF-16 多种编码，逐行校验并返回错误明细，导入默认进入草稿状态
- 提供标准导入模板下载，表头支持同义识别

### 4.5 AI 能力
#### 管理端 AI 小助手
1. **指令型查询**：自然语言转筛选条件，返回结果与直达链接，本地执行不消耗 token
2. **知识问答**：基于站内档案回答非遗相关问题，末尾标注来源出处
3. **内容起草**：批量生成项目简介、历史渊源、技艺特征文案，人工定稿后回填入库

#### 公众端数字讲解员
- 动态虚拟形象「小遗」，播报时带语音波形与环形动画
- 支持语音输入提问，浏览器原生 TTS 播报
- 完全基于本地档案生成讲解词，无额外接口费用

## 五、数据维护与部署

### 5.1 数据存储位置
| 内容 | 路径 |
| :--- | :--- |
| SQLite 数据库 | `data/ich.db`（WAL 模式） |
| 上传附件 | `uploads/年月/` |
| 示例占位资源 | `uploads/seed/` |

### 5.2 备份与恢复
- 备份：停止服务后，复制 `data/` 与 `uploads/` 两个目录即可完成冷备份
- 恢复：停止服务，用备份目录覆盖原目录后重启服务
- 重置演示库：删除 `data/` 与 `uploads/` 目录，重启服务将自动重建示例数据

### 5.3 生产部署建议
- 运行环境：推荐 Node.js 24 LTS，以独立系统账号运行
- 反向代理：使用 Nginx / Caddy 反向代理到本地端口，启用 HTTPS
- 密钥管理：密钥通过环境变量注入，禁止写入代码与前端打包文件
- 运维策略：定期备份 `data/`、`uploads/` 目录，配置日志轮转
